# Qwen3-TTS プレイグラウンド 要件定義

Qwen3-TTS（オープンウェイト版）の機能を、ブラウザから網羅的に試せる Web アプリケーションの要件をまとめる。
前提となる検証結果は [README_spike.md](../README_spike.md) を参照。

## 1. 目的

- Qwen3-TTS の 3 種類のモデル（Base によるボイスクローン、VoiceDesign、CustomVoice）と 2 つのサイズ（1.7B / 0.6B）を、
  CLI を使わずにブラウザから試せるようにする。
- 生成パラメータ、モデルサイズ、seed などの違いを聴き比べ、処理時間・RTF・VRAM と合わせて評価できるようにする。
- VoiceDesign で作った声をクローンして固定の話者にするなど、モデルを組み合わせた使い方を体験できるようにする。
- 作った声と生成結果を社内で共有し、再利用できるようにする。

## 2. 前提と制約

| 項目 | 内容 |
|---|---|
| 利用者 | 社内の少人数（数名）。認証は設けない |
| 実行環境 | 開発者の PC（WSL2 / Ubuntu 24.04、RTX 4090 24 GB）で起動する |
| アクセス | ホスト PC のブラウザ（`localhost`）と、社内 LAN 上の他の PC のブラウザ |
| UI | Gradio |
| コードの配置 | このリポジトリに `playground/` を追加する。`spike_*.py` はそのまま残し、共通処理は整理して再利用する |
| Python / 依存 | 既存と同じ（Python 3.12、uv、qwen-tts 0.1.1、torch 2.14.1+cu130） |
| GPU | 1 枚。生成は 1 件ずつ直列に処理する |

スパイクで分かっている制約:

- RTF は約 1.35〜1.7 で、**生成には音声の長さの約 1.5 倍の時間がかかる**。0.6B にしても速くならない。
- qwen-tts 0.1.1 には本物のストリーミング生成がない（`non_streaming_mode=False` はテキスト入力の模擬のみ）。
- VRAM は 1.7B が 1 モデル約 4〜5 GiB、0.6B が約 2〜3 GiB（生成中のピーク）。何もロードしていなくても Windows 側で約 1.5 GiB を使用している。
- 生成パラメータは README_spike.md の「生成パラメータ一覧」の 10 種類だけが有効（それ以外の kwargs は無視される）。
- 0.6B-CustomVoice は `instruct` に対応していない（黙って無視される）。
- 出力の音量は参照音声の録音レベルを引き継ぐため、小さくなりやすい。

## 3. スコープ

### 対象

- Base 1.7B / 0.6B によるボイスクローン（ICL モード、x-vector only モード）
- VoiceDesign 1.7B
- CustomVoice 1.7B / 0.6B（9 話者、1.7B のスタイル指示）
- 全生成パラメータと seed の指定
- 参照音声のアップロード、録音（ホスト PC のみ）、自動書き起こし、前処理（トリミング、無音除去、正規化）
- 出力のラウドネス正規化
- 話者ライブラリ（クローンした声・デザインした声の永続保存と共有）
- VoiceDesign → クローンの連携ワークフロー
- 条件を変えた並列比較
- 長文の文単位分割と連結、バッチ推論
- 生成履歴（共有）と計測値の可視化
- UI の日本語 / 英語切り替え
- WAV ダウンロード

### 対象外

- 本物のストリーミング生成、文単位の疑似ストリーミング再生（待ち時間を前提とした UI にする）
- 高速化（vLLM、torch.compile、CUDA Graph）。別のスパイクで扱う
- 認証、ユーザーごとのデータ分離
- ボイスクローンの同意確認の仕組み（画面上の注意書きも必須とはしない）
- MP3 など WAV 以外の形式での出力
- 外部向け HTTP API の公開、CLI コマンドや JSON 形式での条件の書き出し
- LAN 上の他の PC からのマイク録音（HTTPS 化はしない）
- ファインチューニング、25Hz トークナイザ

## 4. 画面構成

Gradio のタブで次の画面を切り替える。全画面の上部に、言語切り替えと、キューの状況（実行中 / 待ち件数）を表示する。

| # | タブ | 概要 |
|---|---|---|
| 1 | ボイスクローン | 参照音声から声をクローンして読み上げる |
| 2 | VoiceDesign | 声の説明文から声を作って読み上げる |
| 3 | CustomVoice | プリセット話者で読み上げる |
| 4 | 話者ライブラリ | 保存した声の一覧、試聴、編集、削除。保存した声での読み上げ |
| 5 | 比較 | 同じテキストを最大 4 条件で生成して聴き比べる |
| 6 | 履歴 | 全員の生成結果の検索、再生、条件の再現、削除 |
| 7 | システム | ロード中のモデル、VRAM、計測値の集計 |

## 5. 機能要件

### 5.1 共通の生成フォーム

タブ 1〜4 で共通の部品として、次を持つ。

**テキスト入力**

- F-01: 合成するテキストを入力できる。1 回あたりの文字数に上限を設ける（既定 500 文字。設定で変更可）。上限を超えたら生成ボタンを無効にし、理由を表示する。
- F-02: 例文のプリセット（日本語・英語・中国語ほか、モデルの対応言語）を選んでテキストに挿入できる。
- F-03: 言語を選択できる（`Auto` と対応言語。既定は `Auto`）。選択肢はモデルの `get_supported_languages()` から取得する。

**長文とバッチ**

- F-04: 「文単位で分割」を ON にすると、テキストを文末記号（`。！？.!?`）と改行で分割し、1 文ずつ生成して 1 つの WAV に連結する。
  文と文の間には無音を入れる（既定 0.2 秒。変更可）。進捗は「n / N 文」で表示する。
- F-05: 「バッチ推論」モードでは、1 行 1 テキストで複数のテキストを入力し、`generate_*` にリストで渡して 1 回で推論する。
  結果はテキストごとに別の音声として表示する。バッチと文分割は同時には使えない。
- F-06: 文字数の上限（F-01）は、分割・バッチの場合もテキスト全体の合計に適用する。

**生成パラメータ**

- F-07: seed を指定できる（空欄なら毎回ランダムに決め、決めた値を結果に表示・記録する）。
- F-08: 「詳細設定」の折りたたみ内で、次をすべて指定できる。既定値はモデルの `generation_config.json` の値を表示し、「既定値に戻す」ボタンを付ける。
  - talker: `do_sample`、`temperature`、`top_k`、`top_p`、`repetition_penalty`、`max_new_tokens`
  - sub-talker: `subtalker_dosample`、`subtalker_temperature`、`subtalker_top_k`、`subtalker_top_p`
  - `non_streaming_mode`（既定値はモデルの種類ごとの既定に合わせる）
  - attention 実装（`sdpa` / `flash_attention_2` / `eager`。既定 `sdpa`。`flash_attention_2` は導入済みの場合のみ選択可）
  - モデルサイズ（1.7B / 0.6B。VoiceDesign は 1.7B のみ）
- F-09: attention 実装を変えるとモデルの再ロードが必要になることを、選択時に表示する。
- F-10: 各パラメータに説明（ツールチップ）を付ける。

**後処理**

- F-11: 出力のラウドネス正規化を ON / OFF できる（既定 ON、目標値は既定 -16 LUFS。設定で変更可）。クリップしないようにピークも制限する。

**結果表示**

- F-12: 生成した音声をプレイヤーで再生でき、WAV（24 kHz モノラル）でダウンロードできる。
- F-13: 結果と一緒に、合成時間、音声長、RTF、ピーク VRAM、モデルのロード時間（ロードが発生した場合）、使用した seed を表示する。
- F-14: 生成中は、キューの待ち順、経過時間、推定残り時間（テキスト長と直近の RTF から概算）を表示する。生成をキャンセルできる（待ち状態のものは即時、実行中のものは文分割の場合に次の文の前で中止）。
- F-15: 生成結果はすべて履歴（5.7）に自動で保存する。

### 5.2 ボイスクローン（Base）

- F-20: 参照音声を次の方法で指定できる。
  - ファイルのアップロード（WAV / MP3 / FLAC / M4A など、`soundfile` か `ffmpeg` で読めるもの）
  - ブラウザでの録音。**ホスト PC から `localhost` でアクセスした場合のみ**使える。それ以外では録音部品を無効にし、理由を表示する
  - 話者ライブラリ（5.5）から選択
- F-21: 参照音声の前処理として次を行える。結果は画面上で試聴でき、元の音声と切り替えられる。
  - 区間を指定してのトリミング（波形上で範囲を選択）
  - 前後の無音の自動除去（閾値は既定値あり、変更可）
  - 音量の正規化（既定 ON）
- F-22: 参照音声の長さを表示し、推奨範囲（5〜10 秒程度）を外れていたら警告する（生成は止めない）。
- F-23: 「自動書き起こし」ボタンで、参照音声を Whisper large-v3 で書き起こし、書き起こし欄に入れる。結果は手で修正できる。
  （当初は faster-whisper を想定していたが、この環境では動かないため transformers で動かす。9 章を参照）
  書き起こしの言語は自動判定とし、判定結果を表示する。
- F-24: x-vector only モードを選択できる。このモードでは書き起こし欄を無効にし、品質が下がることを表示する。
- F-25: ICL モードで書き起こしが空のときは生成できないようにする。
- F-26: 同じ参照音声・書き起こし・モード・モデルサイズの組み合わせでは、`create_voice_clone_prompt` の結果を使い回し、再計算しない。
- F-27: 生成後、その参照音声を話者ライブラリに保存できる（5.5）。

### 5.3 VoiceDesign

- F-30: 声の説明文（`instruct`）を入力できる。空でもよい。
- F-31: 説明文のプリセット例（公式の例と日本語の例。年齢・性別・声質・話し方・感情などのバリエーション）を選んで挿入できる。
- F-32: 生成した声を話者ライブラリに保存できる。保存すると、生成した音声と合成テキストを参照音声・書き起こしとして登録し、
  以後はクローン（Base）で同じ声を使い回せる（公式の「VoiceDesign → クローン」の使い方）。
- F-33: 保存の前に、参照音声として使う区間をトリミングできる（F-21 と同じ前処理）。

### 5.4 CustomVoice

- F-40: 話者を選択できる。選択肢はモデルの `get_supported_speakers()` から取得する（9 話者）。
- F-41: 話者ごとのサンプル音声を試聴できる。サンプルは初回起動時（または管理用コマンド）に全話者・日英で事前生成しておき、以後はファイルを再生するだけにする。
- F-42: スタイル指示（`instruct`）を入力できる。プリセット例（感情、話し方など）を選んで挿入できる。
- F-43: モデルサイズが 0.6B のときはスタイル指示の欄を無効にし、0.6B では使えないことを表示する。

### 5.5 話者ライブラリ

- F-50: クローンした声、デザインした声に名前を付けて保存できる。保存先はサーバー上で、全利用者が共有する。
- F-51: 保存する情報: 名前、メモ、作成元（クローン / VoiceDesign）、参照音声（前処理後）、書き起こし、x-vector only かどうか、
  作成元が VoiceDesign の場合はその説明文と生成条件、作成日時。
- F-52: 参照音声と書き起こしを正本とし、`voice_clone_prompt` はモデルサイズごとのキャッシュとして扱う（サイズが違うとプロンプトを流用できない可能性があるため）。
  キャッシュはファイルに保存してよいが、なくても正本から作り直せること。
- F-53: 一覧から試聴、名前・メモの編集、削除ができる。
- F-54: 一覧から選んだ声で、そのまま読み上げられる（中身はクローンと同じ。モデルサイズを選べる）。
- F-55: 同じ名前の話者は登録できない。

### 5.6 比較

- F-60: 同じテキストに対して、条件を変えて最大 4 件を生成し、横に並べて表示する。
- F-61: 条件として変えられるもの: モデルの種類、モデルサイズ、話者（ライブラリ / CustomVoice の話者）、説明文・スタイル指示、生成パラメータ、seed、正規化の有無。
- F-62: 「条件 1 を複製」して一部だけ変えられるようにする。「seed だけ変えて 4 件」のような一括設定も用意する。
- F-63: 各結果の下に計測値（F-13）を表示し、条件の差分（条件 1 と違う項目）を強調する。
- F-64: 4 件はキューに 1 件ずつ積み、終わったものから順に表示する。

### 5.7 履歴

- F-70: すべての生成について、音声、テキスト、モデル、全パラメータ、seed、話者 / 参照音声 / 説明文、計測値、日時、アクセス元 IP を保存する。
- F-71: 全利用者の履歴を 1 つの一覧で表示する。新しい順。モデルの種類、言語、期間、テキストの部分一致で絞り込める。
- F-72: 一覧から再生、ダウンロード、削除ができる。
- F-73: 「この条件で開く」で、該当するタブのフォームに条件を復元できる。
- F-74: 履歴から 2〜4 件を選んで比較画面に並べられる（任意。Phase 3）。
- F-75: 自動削除はしない。システム画面にディスク使用量を表示する。

### 5.8 システム・計測

- F-80: ロード中のモデル、各モデルの VRAM 使用量、デバイス全体の VRAM 使用量と上限を表示する。手動でモデルをアンロードできる。
- F-81: 履歴の計測値を、モデル × サイズごとに集計して表示する（件数、RTF の平均・中央値、合成時間、ピーク VRAM）。
- F-82: RTF と音声長の散布図（モデル別に色分け）を表示する。
- F-83: 環境情報（GPU 名、torch / CUDA / qwen-tts のバージョン、attention 実装）を表示する。

### 5.9 UI の言語

- F-90: UI の表示を日本語 / 英語で切り替えられる（既定は日本語）。ラベル、説明、エラーメッセージ、プリセットの見出しが対象。
  プリセットの説明文・例文そのものは、言語ごとに別の例を用意する。

## 6. モデル管理

- M-01: モデルは使うときにロードする（オンデマンド）。ロードにはキャッシュ済みで約 5〜6 秒、初回はダウンロードで数分かかるので、その旨を進捗に表示する。
- M-02: ロード済みモデルは、(種類, サイズ, attention 実装) をキーとして保持する。
- M-03: VRAM の上限（既定 18 GiB。設定で変更可）を超えそうなときは、最も長く使われていないモデルからアンロードする（LRU）。
  モデルごとの必要量はスパイクの実測値を初期値とし、実際のロード時の増分で更新する。
- M-04: Whisper large-v3 も同じ仕組みで管理する（実測: 重み 2.9 GiB、ピーク 3.4 GiB）。
- M-05: 生成中に CUDA の OOM が起きたら、使っていないモデルをすべてアンロードして 1 回だけ再試行する。それでも失敗したらエラーを表示する。
- M-06: 起動オプションで、起動時にロードしておくモデルを指定できる（既定は Base 1.7B のみ）。
- M-07: 計測前のウォームアップは、モデルのロード直後に 1 回だけ行う（生成のたびには行わない）。

## 7. 非機能要件

### 実行と公開

- N-01: `uv run playground/app.py` で起動する。待ち受けは `0.0.0.0:7860`（変更可）。
- N-02: WSL2 のポートを社内 LAN に公開する手順（WSL の mirrored ネットワーク、または `netsh interface portproxy`、Windows ファイアウォールの許可）を README に書く。
- N-03: Gradio の share リンク（外部公開）は使わない。

### 同時実行

- N-10: GPU を使う処理（生成、プロンプト作成、書き起こし、モデルのロード）は、Gradio のキューで全体で 1 件ずつ直列に実行する。
- N-11: 待ち件数の上限を設ける（既定 20 件）。超えたら受け付けずにメッセージを表示する。

### 性能

- N-20: UI の操作（画面切り替え、履歴の表示など）は、生成中でも待たされないこと（GPU を使わない処理はキューに入れない）。
- N-21: 生成の速度はスパイクと同等（RTF 1.7 以下）であること。プレイグラウンド側の処理で遅くしない。

### データ

- N-30: データは `playground_data/`（`.gitignore` で除外）に保存する。
  - 履歴・話者のメタデータ: SQLite
  - 音声: WAV ファイル（履歴、参照音声、話者サンプル）
  - クローンプロンプトのキャッシュ: ファイル
- N-31: アップロードされた参照音声は、前処理前の元ファイルも保存する。
- N-32: 保存先のパスは設定で変更できる。

### 信頼性・運用

- N-40: 生成の失敗（OOM、不正な入力、モデルのエラー）は、画面にエラー内容を表示し、アプリは落ちないこと。
- N-41: 生成ごとの計測値を、スパイクと同じ形式で `metrics.jsonl` にも追記する（`summarize_metrics.py` で集計できるように）。
- N-42: ログはコンソールとファイルに出す。

### 保守性

- N-50: モデルのロード、計測、生成パラメータの定義は、`spike_common.py` から共通モジュールに切り出し、CLI スクリプトとプレイグラウンドで共有する（CLI の動作は変えない）。
- N-51: 生成処理（モデル管理、前処理、生成、保存）は UI から分離し、UI なしでテストできるようにする。

## 9. リスクと確認事項

- **faster-whisper と CUDA 13 の相性**（Phase 3 で検証済み）: faster-whisper 1.2.1 / CTranslate2 4.8.3 は GPU 推論時に
  `libcublas.so.12` を要求し、この環境（CUDA 13）では動かなかった。PyAV 19 とも非互換だった。
  **transformers の Whisper（同じ large-v3 の重み）に切り替えた。** 日英とも書き起こしは元の文とほぼ一致し、1 件 0.5〜1.8 秒。
- **Gradio のバージョンと機能**（Phase 3 で検証済み。Gradio 6.17.3）:
  - 録音・波形上のトリミングは期待どおり動く。録音はブラウザの制限で `localhost` からのアクセス時のみ。
  - `gr.I18n` が翻訳するのはラベル、説明、プレースホルダー、ボタン、タブ、アコーディオン、Markdown だけ。
    ドロップダウン・ラジオの選択肢、表の見出し、プロットのタイトル、通知（トースト）、進捗表示は翻訳されない。
    そのため選択肢・見出しは日英併記にし、通知と進捗はサーバー側でブラウザの言語（Accept-Language）に合わせて出す。
    画面下の「設定」で表示言語を切り替えた場合、通知と進捗だけはブラウザの言語のままになる。
  - `gr.Number` は空欄を 0 として送るため、「空欄ならランダム」の seed 欄はテキスト入力にした。
- **クローンプロンプトのサイズ間の互換性**: 1.7B と 0.6B で `voice_clone_prompt` を共用できるか未確認。F-52 のとおり、共用できない前提で設計する。
- **ラウドネス正規化の目標値**: -16 LUFS は仮の値。試聴して決める。
- **VRAM 上限の既定値**: 18 GiB は「5 モデル全部（約 17 GiB）は載らないが、1.7B × 3 + Whisper は載る」程度の仮の値。他のアプリと GPU を共有する場合は下げる。
- **ディスク使用量**: 履歴を自動削除しないため、長期間使うと増え続ける。必要になったら削除方針を決める。
- **同意の扱い**: ボイスクローンの同意確認は今回の要件に含めない（社内の少人数での利用のため）。社外に公開する場合は見直す。
